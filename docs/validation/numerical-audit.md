# PR1 数値計算監査

監査日: 2026-10-13。対象ベース: `cb5233a8e420256e02a8e060b0ed162d81601c95`。以下の行番号はこのベースのもの。

**結論: 現在のモデルは格子単位の実験用弱圧縮性流体モデルであり、実地形上の SI 単位の水理計算としては未検証。** 格子単位・完全な kernel support の条件では APIC/MLS-MPM 転送の主要部分と整合するが、異方的なメートル変換、端部の support 欠損、固定小数点の合計範囲に問題がある。PR1 は診断と検証基盤に限定し、既存モデルを変更しない。PLATEAU の精度改善より先に、独立した SI 検証モードの PR を作ることを推奨する。

## 2. 単位と異方的座標変換（重要度: 高）

`MpmParticleObject.ts:614–621` は `x = origin + H q`、`H=diag(Lx/Nx,Ly/Ny,Lz/Nz)` で表示する。一方 `MlsMpmSimulator.ts:655–674` が shader の `real_box_size.xyz` に渡すものはメートル長でなく格子数。計算 shader は全方向のセル幅を 1 としている。名称 `real_box_size` から物理長と判断してはならない。

既定値 (`config.ts:106,170–176`) のセル幅は `(75.490625,22.91875,74.2153125) m`。140 m の単一 `MPM_RENDER_SCALE_M` を実際の変換だと扱うのも誤り。

計算時間を τ、実時間を `t=Tτ`、内部質量 1 あたりを `M kg` と定義すれば、必要な関係は:

```text
u_SI = H v_grid / T
acceleration_SI = H a_grid / T²
rho_SI = M rho_grid / det(H)
volume_SI = det(H) volume_grid
C_SI = H C_grid H⁻¹ / T
```

現在 T と M の定義・記録がなく、`dt=0.05` は秒と確定できない。`gravity_y=-0.12` (`config.ts:145–167,218–219`) を T=1 と仮定すると `g=-2.75025 m/s²`。重力だけ地球重力に合わせる T は約 `0.529573 s` だが、それで圧力・粘性・境界が正しくなるわけではない。

### 圧力・応力

`p2gMomentumStress.wgsl:112–122` は `σq=-pq I+μq(Cq+Cqᵀ)` を使い、`-4 dt V σq d_q` を散布する。H が異方的な場合、世界座標の等方圧力に対応する計算座標応力は:

```text
σq = det(H) T² / M · H⁻¹ σ_SI H⁻ᵀ
pressure part: -det(H) T² p_SI / M · diag(1/hx²,1/hy²,1/hz²)
```

したがって現在の `-p I` に一つの倍率を掛ける修正では SI 等方圧力を表現できない。逆に現在の等方 grid 圧力を表示座標で解釈すると軸ごとに異なる物性になる。EOS の圧縮側音速 `sqrt(5 K/rho0)=sqrt(15/4)=1.93649 grid-unit/time` は、T=1 の表示上で X/Y/Z に `(146.187,44.382,143.717) m/s`。水の音速として校正した数値ではない。

### 粘性

`Cq+Cqᵀ` は格子座標内では Newtonian の対称速度勾配に対応するが、`C_SI=H Cq H⁻¹/T` の対称成分は、H が異方的なら Cq の対称成分のスカラー倍にはならない。よって `MPM_DYNAMIC_VISCOSITY=0.01` を Pa·s と表示できない。体積膨張時の bulk viscosity / 偏差成分補正も指定されていない。物理的剛体回転を異方的 q に写すと Cq が反対称とは限らず、現在の式で人工的粘性応力が生まれ得る。

### 境界と速度コンター

`MpmBoundary.ts:568–597` は壁法線を H を使って格子平面へ変換しており、幾何的な平面の符号は整合する。しかし `updateGrid.wgsl:80–108` と `g2p.wgsl:252–260` は格子の Euclidean 内積で速度を投影する。斜面の摩擦・反発・非侵入速度修正を世界の運動エネルギーに対して解釈するには H² の計量、または SI 速度・SI 法線での応答が必要。軸に揃った摩擦なし壁では法線除去は一致するが、一般斜面や摩擦では一致しない。

`copyPosition.wgsl:28–30` のコンターは `length(v_grid)`。実流速は `length(H v_grid)/T` なので、方向が異なる同じ内部速度の見かけの SI 速度は異なる。現行値は grid-unit/time として扱う。

## 3. MLS-MPM 各段階

### P2G と G2P の照合

完全な 3×3×3 support、無限精度、内部等方格子幅 1 の場合、現在の cell-center quadratic B-spline は `Σw=1`, `Σw d=0`, `Σw ddᵀ=I/4` を満たす。半セル offset 自体は誤りではない。

```text
m_i = Σp w_ip m_p
momentum_i = Σp w_ip [m_p (v_p+C_p d_ip) - dt V_p σ_p (4I) d_ip]
v_i = momentum_i/m_i + dt g
v_p_new = Σi w_ip v_i
C_p_new = (Σi w_ip v_i d_ipᵀ) (4I)
q_p_new = q_p + dt v_p_new
```

`p2gMass.wgsl:65–104`、`p2gMomentumStress.wgsl:121–138`、`updateGrid.wgsl:358–365`、`g2p.wgsl:479–520` はこの転送形と整合する。c0/c1/c2 を列として使う向きも一致する。圧力が正なら σ=-pI、その前の負号で反発方向の力になる。

ただし現在体積 `Vp=mp/rho_p` を使うため、参照体積 V0 と Kirchhoff 応力 / `P Fᵀ` を使う式とは表記が違う。Cauchy 応力を用いて V を掛けること自体は整合し得る。F/J を保存していないことだけで誤実装とはいえないが、密度推定法の妥当性は別に検証が必要。

### 密度・EOS（重要度: 高）

`p2gMomentumStress.wgsl:90–119` の密度は `rho_p=Σi w_ip m_i`。セル体積 1 の内部単位での二重平滑化した密度推定であり、SI ではセル体積除算が必要。粒子分布、free surface、壁の欠損 support で値が変化する。連続式を独立に積分した密度ではなく、密度比コンターを測定済み真値とは解釈しない。

EOS は `p=max(0, K[(rho/rho0)^5-1])`。指数 5 の Tait 型、負圧を切り捨てる経験的モデルである。非圧縮水を解く圧力 Poisson 法ではない。参照密度以下では圧力も圧縮剛性も 0、参照点で微分が不連続。密度 floor 1e-4 はゼロ除算防止であり物理的真空境界の定式化ではない。正圧域の `c²=(5K/rho0)(rho/rho0)^4` から、圧縮で安定時間刻みが急激に厳しくなる。

`MlsMpmSimulator.ts:752–784` は grid 体積×参照密度を粒子数で割り、粒子数上限でも総内部質量を維持する。これを kg と同一視してはならない。初期配置の x/z/y clamp (`:816–832`) は粒子を同じ付近に集め、局所高密度や初期圧力波を作り得る。粒子間隔を変える検証では同じ体積・同じ総質量を確認する。

### 質量保存と端部欠損（重要度: 高、解析的反例あり）

粒子の active flag と一粒子質量は step 中に変わらないため、`activeCount×particleMass` は一定。しかしそれだけでは格子上の質量保存を検証したことにならない。

`p2gMass.wgsl:90–93` は領域外セルを捨てる。`g2p.wgsl:513–518` は y を `[0.02,Ny-0.02]` まで許す。粒子 y=0.02 の kernel の下側セル y=-1 は重み `0.5*(1-0.02)^2=0.4802`。x/z に欠損がない単粒子でも格子へ渡る質量は `0.5198 mp` に過ぎない。y=Ny-0.02 も対称。粒子データから質量が消えるのではなく、各 step の grid transfer が 48.02% 欠損する反例である。

G2P も領域外速度をゼロとして扱い (`g2p.wgsl:96–105`)、重みを再正規化しないため、一様接線速度も端部で減衰する。`D⁻¹=4I` が切断 support では成り立たず affine 再現性も失われる。単純な重み再正規化だけでは一次モーメント/角運動量まで修復できない。独立修正 PR で ghost nodes、余白、または境界対応 transfer を比較する。

### 境界応答

grid は法線反発と Coulomb 型接線投影、G2P は侵入法線速度だけ除去する。二重の反発を避ける意図は明確だが、G2P で補正する前の C はそのまま残る (`g2p.wgsl:505–507,561–568`)。位置投影も力積・仕事と対応する厳密な接触解ではない。静止水柱の壁面圧力、運動量、エネルギー、壁摩擦の grid 依存性は未検証。地形/建物の detailed geometry は別の衝突監査を参照。

## 4. 固定小数点と atomicAdd（重要度: 高）

倍率 S=1e7。符号付き i32 の最大復号値は `214.7483647`。この範囲はその buffer が保持する **質量、各運動量成分、更新後速度** ごとに適用される。

- `p2gMass.wgsl:29–32,101–104` と `p2gMomentumStress.wgsl:32–34,136–138` の clamp は一回の寄与だけを制限する。合計が範囲内とは保証しない。例えば 150 を 2 回 atomicAdd すると `3,000,000,000` が i32 で `-1,294,967,296`、復号 -129.4967296 になる。個別 clamp に抵触しない。
- 正の質量のみでも集中すれば overflow する。参照密度4に対してセル質量上限は約53.69倍だが、応力・速度による運動量 overflow はそれより早く起こり得る。平均密度だけでは安全性を示せない。
- 混合符号の部分和 overflow は modulo 演算として起こる。最終数学和が表現範囲内で途中を読まなければ剰余が戻り、部分和 overflow だけで最終値が必ず壊れるわけではない。最終和、個別飽和、次 pass で読む時点を区別する。安全側監視には各セルの絶対寄与和を利用できる。
- `updateGrid.wgsl:354–356` は mass<=0 のセルを return するが、その vx/vy/vz を消さない。質量 overflow、あるいは質量が量子化でゼロでも運動量は非ゼロという場合、`g2p.wgsl:96–105` は残った **運動量を速度として** 読める。
- 変換は truncation なので、非負質量は寄与ごとに最大 1/S 未満を切り捨てる（入力 float 計算誤差を除く）。完全 support・50万粒子・27寄与なら総質量誤差の上限は 1.35 内部質量未満。float32 掛算丸めを含む GPU の厳密上限ではない。f32 は大きな整数を全て表現できず、S=1e7 でも常に 1e-7 の実効精度は得られない。
- 単項飽和は質量や力を失わせる。対称な応力寄与が別々に飽和すれば作用反作用の釣り合いも壊れる。速度の component clamp も速度方向と運動エネルギーを変える。発散が見た目上止まっても正解にはならない。
- `clamp` は NaN/Inf の安全な回復装置ではない。WGSL の有限値仮定も考慮し、後段 readback の非有限判定に加え、飽和前の危険度・密度比・最大速度を監視すべき。

対策候補は mass/momentum の別スケール、ブロック単位 reduction、負荷上限の事前評価と観測カウンター。スケールを小さくするだけでは精度が低下する。これらは PR3 の「同じ数値結果」の高速化とは分離する。

## 5. 時間刻み・空間収束

`setDt` (`MlsMpmSimulator.ts:394–397`) は下限だけで、安定条件の上限を設けていない。下限1e-5は発散を防ぐ保証ではない。有限値の入力検証も必要。`simulatedTime = substeps×currentDt` (`:580`) は途中で dt を変えると過去の時間も再計算するため、物理時間履歴として誤る。以降の検証は dt 固定で走らせ、可変 dt のモードでは各 step を積算する。

明示法の検証では少なくとも次の制約を監視する（係数は方式ごとに検証し、下式を無条件の安定保証としない）。

```text
dt ≲ C_adv min_j hj / (|uj|+c)
dt ≲ C_visc / [ν (1/hx²+1/hy²+1/hz²)]
ν = μ/rho
```

現行 grid-unit モードでは hj=1 として判断する。圧縮側参照音速だけなら dt*c≈0.0968 だが、最大速度・最大密度比が不明なので既定 dt が安定とは断言できない。μを増す操作にも明示拡散制限が必要。

Nxだけを変更して同じK/μ/g/dtを使うと、同じ物理問題を細分化した収束試験にはならない。固定 L と SI 物性、同じ実時間、同じ初期体積・粒子質量総和、同じ境界位置を維持して初めて grid convergence を評価できる。32³/64³/128³ で h に応じた dt、粒子数/セルを明記する。

## 6. PR1 の検証解釈と次の合格基準

PR1 の CPU 再現・解析テストは shader の式の問題点を再現する道具であり、GPU 実行、shader コンパイル、原子的競合、描画の正しさを代替しない。既知不具合を再現してテストが通ることは「不具合を修正した」ことではない。

| 問題 | 比較対象 / 記録項目 | 到達していない検証 |
|---|---|---|
| 閉領域質量保存 | 粒子総質量と grid総質量を別記、端部欠損、overflow、飽和数 | 実機GPUで長時間の保存性 |
| 平面壁衝突 | 摩擦なし平面で入射/反射法線速度、接線速度、位置非侵入 | 斜面・反発係数・摩擦のSI一致 |
| 静止水柱 | 速度ノルム、重心、密度比、圧力鉛直分布、壁面力 | 定常状態、収束、検証済みソルバーとの一致 |
| 平坦床ダムブレイク | front位置、重心、エネルギー、密度、質量、dt/h感度 | 公開実験データとの定量比較、3D収束 |

非圧縮静水の目標は `p=rho g(H-y)` だが、これは現在の弱圧縮EOSの厳密解ではない。指数γ=5、自由面rho=rho0の圧縮側静水なら、EOSと `dp/dy=-rho g` から

```text
r(y) = [1 + (γ-1) rho0 g (H-y)/(γ K)]^(1/(γ-1))
p(y) = K [r(y)^γ-1]
```

を得る（r=rho/rho0、gは正の大きさ）。現行粒子再構成密度・free surface補正を含む離散解がこれへ収束するかは未検証。一様密度・速度ゼロで初期化した水柱は圧力支持がないため、そのまま初期静止を合格条件にしてはならない。

乾床 dam-break の浅水理論 front `2 sqrt(gH)t` は、浅水・無摩擦・初期条件の理想化であり、初期瞬間から3D圧縮性粘性流体の厳密解として採点しない。将来の公開ベンチマーク比較では実験の寸法、ゲート、壁摩擦、測定時刻、無次元化を固定する。

## 7. 独立 SI 検証モードの最小設計（次 PR）

1. 現行 `legacy-grid-experimental` を既定のまま保存。新 `si-validation` は別シーン・別パラメータ・別結果 schema とし、検証が済むまで地形デモを置換しない。
2. 原点を局所 ENU、粒子位置m、速度m/s、質量kg、密度kg/m³、圧力Pa、粘性Pa·s、dt秒と定義。GPU は局所原点で大座標のfloat32精度損失を避ける。
3. 初回は等方 h の box を選び、`D=diag(hx²,hy²,hz²)/4` を明示。重みは `q=H⁻¹(x-origin)` で評価し、転送距離はm。`C=Σw u_i d_iᵀ D⁻¹`、応力散布 `-dt V σ D⁻¹ d_i` を使う。異方格子はその後の個別試験にする。
4. `rho_i=m_i/(hx hy hz)`、粒子の体積・密度更新法を比較して選定。ghost supportとfree surfaceで密度が偏るため、セル体積除算だけで検証完了にしない。質量と運動量の固定小数点はSI値を直接1e7倍せずスケール設計を別途行う。
5. 境界は世界法線と SI 速度で解く。表示 mesh、collision geometry、solver grid を分離。単純平面から検証し、実地形へ進む。
6. 解析ベンチマーク、CPU/GPU同一初期条件比較、dt半減、h半減、overflow診断が合格した段階でのみ、物理単位の表示と適用範囲を拡張する。

## 8. GPU 性能調査で確認した範囲

`MlsMpmSimulator.ts:497–505,513` は粒子段階を buffer capacity の `particleCount` で dispatch し、各 shader は active flagでreturnする。reset後のactive粒子は `createDamBreakParticles` により先頭から連続配置されるため、activeCount dispatch は候補。ただし将来 sparse inactive や kill が入る場合、末尾だけの削減では不十分。copyPosition の inactive描画消去とreset初期化も保持する必要がある。

PR1では計算dispatchの変更、速度向上の主張はしない。Timestamp Query未実施なら GPU ms とせず CPU submission/wall-clock と明記。P2G mass/応力/grid/G2P に加え、境界は各passに内包されるため、pass全体時間から境界だけの時間を推定したときは推定と記す。物理step数を減らしたFPS向上は計算高速化には数えない。
