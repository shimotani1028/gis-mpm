## 1. 現在の表示形状と物理形状

入力から物理境界までの経路は次のとおり。

1. `src/import/plateauCityGmlParser.ts:130-178,188-258` は `lod0FootPrint`、なければ `lod0RoofEdge` を抽出し、`lod1Solid` から高さの最小・最大のみを得る。任意の CityGML 三角形メッシュを保持する読込器ではない。複数の `posList` はそれぞれ独立した Polygon になり、外周・穴の位相を保存しない。
2. `src/import/BuildingObstacleLayer.ts:194-265,625-664` は外周 `polygon[0]` を押し出す。建物高さは `measuredHeight` 優先で最低 1 m、屋上は `max(baseHeights) + buildingHeight` の水平面。元の傾斜屋根・穴は表示段階で失われる。
3. 同ファイル `:295-367` は上面高さを返す heightfield サンプルと、水平輪郭の符号付き距離・水平法線・単一の基部/頂部高さを返す側面サンプルを別々に提供する。
4. **通常の UI 適用経路では、建物上面は衝突用 heightfield に含まれない。** `src/main.ts:2583-2614` は衝突地形を DEM のみにし、建物上面を合成した高さ場は初期粒子配置専用にする。`TerrainBoundary.fromTerrain` 自体は上面合成が可能なので、API の機能と通常の利用経路を混同しない。
5. `src/mpm/boundary/MpmBoundary.ts:510-613` は各 XZ サンプルに最良の側面を一つだけ焼き込む。GPU は最近傍の 2D サンプルを選び、その接平面で距離を外挿する（`g2p.wgsl:197-248`、`updateGrid.wgsl:265-345`）。これは完全な 3D SDF ではない。

### 5 形状の比較

| 形状 | 現在の表示 | 現在の衝突と構造的制限 | PR2 で必要な比較 |
|---|---|---|---|

| 隣接 2 棟と通路 | 両方の外周は表示可能 | 各 XZ セルに一つの側面だけを保存。近い壁への切替で法線が不連続になり、細い通路の両面を同時表現できない場合がある。格子側の厚みは最低 0.5 計算セル（`updateGrid.wgsl:340`）で、境界サンプルを細かくしても計算格子の粗さは解消しない | 通路幅/計算セル幅を 0.5, 1, 2, 4 に変え、通過質量、閉塞率、壁位置誤差を記録。境界サンプル数も別に変える |

| 開口部のある障害物 | 外周だけを押出し、穴や門形の開口が埋まる | GeoJSON 内周は無視。CityGML 内周も独立した Polygon となり得る。XZ ごとの単一高さ区間では門型の下面と上面を含む一般形状を表せない | 中庭型の水平穴と、門型の上下に固体がある開口を区別。開口の占有率・流量と solid 内粒子数 |
| 高架 | 取得可能な footprint と高さ範囲による柱状近似。橋梁専用モデルの読込ではない | terrain-draped の基部は地形に接地させられ、元の桁下空間を保持できない。側面に単一 base/top はあるが、下面接触も 3D 位相もない | 橋脚と桁を別 solid とする合成 fixture。桁下通過と桁上接触を同じケースで確認 |

小建物を見逃さないための `sampleHeight` の膨張半径は境界サンプル間隔の半対角長（`MpmBoundary.ts:625-635`）。通常は初期配置で使われるため、「建物に水を置かない領域」が表示 footprint より広がり、細い通路の初期粒子を排除する可能性もある。側面の検索半径はさらに `0.75 * max(hx,hz)` を加えるが、これは壁自体を同じ量だけ拡張する処理ではない。

G2P は移動後の近傍接平面で前位置との crossing を推定して復帰する（`g2p.wgsl:338-464`）。線分と全障害物の連続衝突判定ではない。1 ステップで薄い建物を横断し、移動後地点に有効な側面がなければ検知できない可能性がある。側面補正後は領域 clamp をするが地形の再補正はない（`:531-558`）。角・斜面・複数障害物の同時接触を未検証とする。

### LOD の制限

LOD0 footprint/roof edge がない建物は `rings.length === 0` で対象外。LOD1 は高さ範囲に縮約され、元 solid の面形状は使わない。LOD2/3 の屋根・開口等がファイルに含まれていても現在の経路はその形状を使用しない。「PLATEAU 読込成功」を「元 LOD の物理形状を再現」と表示しない。後続 UI には入力 LOD と実際に使用した近似（footprint extrusion / side-only）を別々に保持する。

## 2. 座標・標高・法線

- 水平変換は `src/geo/tileMath.ts:108-144` の球半径を用いた局所正距円筒近似で、厳密な測地系変換や ECEF からの ENU 回転ではない。`x=East, z=North, y=height` を使う。コメントの「数十 km で cm 級」は精度検証の証拠にはならない。緯度による水平縮尺の変化を無視するため、中心から離れた位置では長さの誤差が生じる。
- `plateauCityGmlParser.ts:263-307` は最初の 2 数値を緯度・経度と固定解釈し、`srsDimension` は見るが `srsName` に応じた座標参照系や軸順の変換をしていない。投影座標系や別軸順のデータを一般にサポートするとは言えない。
- 高さは入力数値を直接メートル値として使用し、標高基準・楕円体高/標高の変換を持たない。DEM の数値デコードができることと CityGML の高さ基準が合うことは別問題。正確性の主張には配布データの CRS、鉛直基準、計測年の記録と基準点比較が必要。
- `BuildingObstacleLayer.ts:607-622` の terrain-draped は footprint 各頂点の底面を DEM に合わせ、失敗時だけ元高さへ戻す。`main.ts:1807,1857` 等でこれを使用する。見た目の浮きは減っても、元標高を検証したことにはならない。底面は頂点ごとに異なる一方、側面衝突の `baseHeight` は最小値、`topHeight` は最大底面+高さなので、斜面下側/上側で表示形状と衝突区間がずれる。
- DEM と建物は共通 AOI 原点を使う設計だが、再読み込み時の原点変更・地形サンプルの LOD・Float32 化の影響は既知基準点で確認する必要がある。地形の missingSamples/clampedSamples（`MpmBoundary.ts:228-293`）も結果と一緒に保存する。

異方的なセル幅を `D=diag(hx,hy,hz)`、世界位置を `x=o+Dq` とすると、世界の平面法線 `n` は格子上で `ng = normalize(Dᵀn)` になる。側面の CPU 変換（`MpmBoundary.ts:566-592`）は平面の幾何表現としてこれに一致する。しかし GPU の衝突速度投影は格子座標のユークリッド内積を使う。例えば滑り境界の `vq' = vq - (vq·ng)ng` を世界に戻すと `v' = v - D ng ngᵀ D⁻¹ v` になり、物理空間の `v - n nᵀ v` と一般には一致しない。地形法線・摩擦・反発にも同じ計量の問題がある（`updateGrid.wgsl:80-107`）。位置が合うだけでは物理的な反発方向・エネルギーを保証できない。単位系修正 PR では速度と接触応答を世界 SI 座標で扱うか、変換計量を式全体に導入し、斜面・斜め壁の基準解で確認する。

## 3. GPU 性能の調査と PR3 の測定設計

`MlsMpmSimulator.ts:478-521` は既に batch を 1 回 submit、各 step を 1 compute pass、grid clear を clearBuffer、描画転送を batch 最後の 1 回にまとめている。これらを新規改善として数えない。

P2G mass、P2G stress/momentum、G2P、copyPosition は buffer 容量 `particleCount` で dispatch する（`:497-517`）。初期粒子は連続した先頭領域へ配置され、残りは inactive sentinel（`:701-723`）、有効数は `activeParticleCount`（`:469`）。各 shader の inactive early return は余分な workgroup の起動を防げない。PR3 の第一候補は active な先頭範囲の dispatch。ただし将来 kill/reseed で途中に穴ができた場合は live count と最大有効 index を区別する。copyPosition の範囲を縮めるなら reset 時の末尾 sentinel 更新と描画個数を検証する。丸めた最終 workgroup の余りは inactive guard で扱う。

| 計測対象 | 分離方法 | 解釈 |
|---|---|---|
| P2G mass、stress/momentum、updateGrid、G2P、copy | 利用可能な環境で timestamp-query に対応した計測用 pass 分割。通常 pass の結果とも比較 | pass 分割自体の追加コストを報告。未対応なら測定不能を明記 |
| 境界衝突 | updateGrid/G2P に内包。境界なし/ありの対照実験と全体時間を併記 | 差分は粒子分布も変えるため純粋な境界カーネル時間とは呼ばない |
| 水面・地形描画 | 計算を固定して各描画経路を個別計測、通常描画とも比較 | offscreen size、解像度倍率、画面サイズ、camera を固定 |
| timestamp 非対応 | submit の CPU 時間と、queue 完了待ちを含む batch 経過時間を別々に記録 | 完了待ちはキュー遅延・CPU/driver を含む。GPU 時間への改名は禁止 |

容量を 50k/200k/500k、active 比率を 25%/100% とし、同じ初期粒子、dt、step 数、乱数 seed、境界、描画条件で変更前後を比較する。warmup 後、中央値/p95、step/s、FPS、非有限粒子数、最大速度、位置・速度差（最大/RMS）、粒子質量と grid 転送量を記録する。atomic の加算順・固定小数点飽和の影響も確認し、変更差を一律 bitwise 一致で判定しない。ベンチマーク用 readback を通常描画ループへ混ぜない。

**実測結果: 未実施。高速化率・FPS・GPU メモリ実使用量は未検証。** 計算ステップを減らす変更はこの比較に含めない。

## 4. 可変格子の実装準備

既定格子は `config.ts:106` の 64³、境界は独立した 384²（`:125`）。`MpmBoundary` は X/Y/Z セル数を持てるが、`MlsMpmSimulator.ts:168` と `MpmParticleObject.ts` の多数箇所（`:305,330-332,618-620` 等）はグローバル定数に依存する。設定定数だけ切り替える UI ではなく、simulation instance の GridSpec を全経路へ渡す。

`MlsMpmSimulator.ts:45-64,234-318` の明示バッファだけの見積りは `112P + 16NxNyNz + 64BdBw + 272` bytes。これは粒子 80、位置 16、描画属性 16 bytes/粒子、格子 16 bytes/セル、境界 2 面×32 bytes/サンプル、平面 192・uniform 80 bytes。CPU 配列、Three.js 内部コピー、readback、水面 render target、地形・建物・テクスチャ・driver 分を含まない。

| 格子 | 格子バッファのみ | P=500,000, 境界384²の明示バッファ合計（概算） |
|---|---:|---:|
| 32³ | 0.5 MiB | 62.91 MiB |
| 64³ | 4 MiB | 66.41 MiB |
| 128³ | 32 MiB | 94.41 MiB |

GPU 総空きメモリが正確に分かるとは仮定せず、device limits の単一 buffer/storage binding 上限、workgroup 上限、推定総量、allocation の validation/error、device loss を確認する。3D 格子全体を 1 次元 dispatch する現在の方法では `ceil(NxNyNz/128)` も確認する。128³ の選択可否は能力検査と短い試行の両方で判断し、失敗時は粒子状態を破壊せず設定を戻す。

SI モードのセル幅は各軸 `hi=Li/Ni` として gradient、APIC の moment inverse、応力、接触、dt 安定条件を一貫して導出する。解像度比較では粒子数一定と particles-per-cell 一定を分ける。道路/通路幅が数セル未満なら「流量精度未検証」の警告を候補とする。境界384²が高精細でも64³の運動量格子の精度を代替しない。幅/セル幅の警告閾値は収束試験で確定する。

## 5. 共有データと後続 PR の順序

以下は設計案で、実装済み API ではない。

- `GeoReference`: 水平 CRS、鉛直基準、原点、axis、出典と取得時刻。各変換と誤差・不明な基準を明示。
- `TerrainDataset` / `GeometryAsset`: ソース形状を不変で保持。描画 mesh と collision mesh は別派生物として出典 ID で結ぶ。
- `CollisionRepresentation`: heightfield / extrusion / triangle mesh / voxel / SDF の capability と解像度、開口・overhang 対応を宣言する。solver ごとの物理格子へ変換する adapter を持つ。
- `SimulationCase`: 単位、材料、境界、時間刻み、初期条件、solver/version と検証状態を保存する。legacy 格子単位と SI を黙って混ぜない。
- `Solver`: prepare / step / diagnostics / snapshot / dispose。MPM 固有バッファを共有 interface の必須要素にしない。GPUDevice や地形を共有しても、内部状態と安定条件は solver が所有する。
- `ResultFrame`: 時刻、座標系、物理量と単位、検証タグ、必要なら粒子/剛体/格子場を可視化 adapter へ渡す。水面 renderer を剛体運動側へ強制しない。

SDF は滑らかな法線と開口/高架への対応候補、voxel は位相を持つ占有表現の候補。ただし thin wall の消失、符号決定（閉じていない mesh）、distance 精度、3D memory、生成時間、帯域を現方式と同じ fixture で比較してから採用する。2D 側面方式が十分な建物への fallback は残す。

| PR | スコープと受入条件 |
|---|---|
| PR1 | 現行式・単位・境界の監査、CPU 検証基盤・独立 GPU 診断、検証範囲を明記した再現手順。既存式を維持 |
| PR1 の後の単位系 PR | 既存 legacy を保持した独立 SI 検証モード。異方格子の重力・応力・斜面接触の基準解、静止水柱、dt/格子収束を確認。問題の規模から衝突改善より優先する候補 |
| PR2 | 上記 5 形状の fixture と表示/物理形状の比較を先行。屋根欠落・通路・開口の適用範囲表示を含め、採用する境界修正を限定して別 PR に分割可 |
| PR3 | まず計測追加、その後 active 範囲 dispatch。計算結果差、step/s、FPS、メモリ見積り/観測可能量、発散の有無を固定ケースで比較 |
| PR4 | instance GridSpec と能力検査、32/64/128 と異方格子。単位系/収束結果なしで「高精度」と表示しない |
| PR5 以降 | 共有地形/衝突/結果 adapter。落石は並進・回転、反発・摩擦を持つ剛体方式を独立 solver として検証。斜面崩壊は土の弾塑性構成則を持つ MPM 等を材料単体試験から検討。土石流は混相/粒状体との運動量交換・体積率・抗力の選択と質量/運動量検証を先に設計。まとめて実装しない |

各後続 PR に変更ファイル、前の問題、修正、数値比較、性能、残存問題、新制限、再現手順を添付する。実データの見た目だけで物理検証に合格したとはしない。この実験プロジェクトの結果を災害予測・避難判断・土木設計向けの検証結果として扱わない。
